# Task 28: ボトラー分離をデータ駆動にする（ハードコード特殊対応の是正）

## 背景

Task 27 でボトラーとブランドの分離を要件にしたが、実装は
`_separate_golden_cask_macduff`（`scripts/extract_whiskey_names_claude_sonnet.py:219`）という
**タスク文に例として挙げた「ゴールデンカスク / マクダフ」の組をそのままハードコードした関数**になった。

実データで測ったところ、これでは全く足りない。

**楽天 1,000 件中、独立ボトラー物は 53 件（5.3%）、8 社以上にまたがる:**

| ボトラー | 件数 | 例 |
|---|---|---|
| Douglas Laing | 12 | `ダグラスレイン プロベナンス カリラ 8年` |
| Gordon & MacPhail | 11 | `タリバーディン 16年 2008 リフィルバーボンバレル カスク` |
| Hunter Laing | 10 | `オスロスク 11年 2011 リフィルホグスヘッド オールド モルト カスク` |
| Signatory | 5 | `シグナトリー ポートダンダス 15年 2006 43% 700ml` |
| Berry Bros | 4 | `ベンリネス 13年 2010 スモールバッチ (BBR ベリーブラザーズ)` |
| Kingsbury | 3 | `モートラック 30年 キングスバリー サー オービル 1995` |
| Golden Cask | **2** | `ゴールデンカスク マクダフ 10年 2012` |
| Boutique-y | 2 | `ブティックウイスキーカンパニー ワールドウイスキーブレンド` |

**ハードコードが救うのは 53 件中 2 件（4%）にすぎない。**

実害は具体的である:

```
「ダグラスレイン プロベナンス カリラ 8年」
  → brand_ja: "ダグラスレイン プロベナンス カリラ"
```

存在しないブランドがカタログに登録され、**さらに正規の「カリラ」の照合を汚染する**
（`カリラ` を含む別ブランドが増えると一意性ゲートが発火し、カリラが `ambiguous` に落ちる）。

**例をハードコードするとテストは緑になるが、問題は残ったまま見えなくなる。** これが最も避けたい形である。

## 対象リポジトリ

`/home/ttakahashi/workspace/whiskey`（ブランチ `fix/brand-detection-canonical-name`）

## スコープ

`scripts/` と `tests/` のみ。`lambda/` `infra/` `frontend/` は触らないこと。

## 実装内容

### 1. `scripts/catalog/bottlers.json` を新設（人手の正本）

`brands.json` と同じ思想で、独立ボトラーの正本を人手で書く。

```json
{
  "version": 1,
  "bottlers": [
    {
      "bottler_key": "douglas_laing",
      "bottler_ja": "ダグラスレイン",
      "bottler_en": "Douglas Laing",
      "aliases": ["ダグラスレイン", "ダグラス・レイン", "Douglas Laing",
                  "プロベナンス", "Provenance", "オールドパティキュラー", "Old Particular"]
    }
  ]
}
```

上表の 8 社を最低限すべて含めること。シリーズ名（`プロベナンス` / `オールド モルト カスク` /
`スモールバッチ` 等）もボトラーの手掛かりなので `aliases` に入れてよい。

**別名は人手で書く。モデルに生成させないこと。**

### 2. ハードコード関数の削除

`_separate_golden_cask_macduff` を**削除**し、`bottlers.json` を引くデータ駆動の処理に置き換える。
**特定のボトラー名をコード中にリテラルで書かないこと。**

処理:

1. `source_title` を正規化し、`bottlers.json` の別名にマッチするか調べる
2. マッチしたら `bottler_key` / `bottler_ja` / `bottler_en` を設定する
3. モデルが返した `brand_ja` / `brand_en` に**ボトラーの別名が含まれていたら除去**し、
   残った蒸留所名をブランドとする
4. 除去した結果ブランドが空になる場合は、`brand` を `null` にして
   §4 のレビュー対象に回す（推測で埋めない）

### 3. プロンプトの改善

`bottlers.json` の一覧を**プロンプトに参照リストとして渡す**。

指示の要点:
- タイトルに既知のボトラーが含まれる場合、`bottler_*` にボトラー名、
  `brand_*` には**蒸留所名**を入れる
- ボトラー名を `brand` に含めない
- 未知のボトラーらしき表記があれば、推測でブランドに混ぜず `null` にする

**プロンプトに特定の組（ゴールデンカスク/マクダフ）を唯一の例として書かない。**
複数のボトラーを例示するか、参照リストに委ねること。

### 4. 未知ボトラーのレビュー出力

`brands.json` に対する `proposed_brands.json` と同じ扱いで、
**未知のボトラーらしき表記を `scripts/catalog/proposed_bottlers.json` に出力**する。

- 提案する `bottler_key`、観測された表記、出現件数、代表的な元タイトル 3 件
- 出現件数の多い順
- **`bottlers.json` には自動マージしない**（人手の承認を経る）

判定の手掛かり: 「蒸留所名 + 年数 + ヴィンテージ + カスク種別」の並びで、
先頭に既知ブランドでない語がある場合など。確実でなければ提案に留め、
`brand` を `null` にしてレビューに回すこと。

### 5. `catalog_key` への反映

ボトラーは商品同一性に**含める**（Task 26 の方針どおり）。
同じ蒸留所・同じ年数でもボトラーが違えば別商品になることをテストで固定する。

## テスト（Bedrock を呼ばないこと。モデル応答はスタブ）

**ハードコードでは通らないケースを必ず含めること:**

1. `ダグラスレイン プロベナンス カリラ 8年` →
   `brand_ja == "カリラ"`, `bottler_ja == "ダグラスレイン"`
2. `シグナトリー ポートダンダス 15年 2006` →
   `brand_ja == "ポートダンダス"`, `bottler_ja == "シグナトリー"`
3. `モートラック 30年 キングスバリー サー オービル 1995` →
   `brand_ja == "モートラック"`, `bottler_ja == "キングスバリー"`
   （ボトラーが**先頭ではなく途中**に現れるケース）
4. `ゴールデンカスク マクダフ 10年 2012` → 従来どおり正しく分離される（回帰）
5. **ボトラー名がコード中にハードコードされていないこと**:
   `bottlers.json` から 1 社を削除したら、その社のタイトルが分離されなくなる
   （＝ロジックが JSON 駆動であることの証明）
6. 同一蒸留所・同一年数でボトラーが異なる 2 商品が**異なる `catalog_key`** になる
7. 未知のボトラーらしき表記が `proposed_bottlers.json` に出力され、
   `bottlers.json` は変更されない
8. ボトラー除去後にブランドが空になるケースで `brand` が `null` になり、
   推測で埋められない
