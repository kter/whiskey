# AI によるブラウザ確認

画面に関わる変更をしたエージェントが、ヘッドレスブラウザで自分の変更を確かめる手順。合否の正本は `make e2e`（Playwright のスモークテスト）で、ここに書くのはそれでは拾いにくい見た目と操作感の確認。

## いつやるか

- `frontend/` の画面・スタイル・文言を変えたとき
- API の応答の形を変え、画面の表示に影響しうるとき
- 文書や Lambda だけの変更では不要

## 手順

1. `make e2e` を通す。クラウドでは `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` を付ける（パスは AGENTS.md の「各クラウドの実測」）。
2. 確認用にスタックを起動したままにする。

   ```bash
   make local-up && make local-init
   make api &                                   # 127.0.0.1:8000
   (cd frontend && NUXT_PUBLIC_MOCK_AUTH=1 NUXT_PUBLIC_API_BASE_URL=http://localhost:8000 npx nuxt dev --port 3000 --host localhost) &
   ```

   起動の仕方は `scripts/local/e2e.sh` と揃えてある。origin は `http://localhost:3000` を使う（API と S3 の CORS がこの origin だけを許可している）。`--host 127.0.0.1` にすると、`localhost` が `::1` に解決される環境で繋がらないことがある。
3. Playwright（スクリプトか Playwright MCP）で、変更した画面を下の観点で操作し、スクリーンショットを撮る。
4. 終わったら自分が起動したプロセスだけを止め、`make local-down` で moto を止める。`pkill -f` はシェル自身に当たることがあるので使わない。

## 観点

各画面で次を確かめる。

- **スマホ幅（390×844）が標準。** 写真を撮る用途なので、まずこの幅で崩れがないか。必要ならデスクトップ幅も
- **コンソールエラーとネットワークエラーが無いこと**（4xx/5xx、CORS エラー）
- **ダークモード**（`colorScheme: 'dark'` をエミュレート）で文字が読めること
- **状態を色だけで区別していないこと。** 選択中・エラーなどは、色に加えてマークや文言でも分かること（621 のブラウザでは Dark Reader が色の差を潰す。ヘッドレスでは再現しない）
- 変更した文言が意図どおり表示されること。日本語の折り返しで崩れていないこと
- 主な操作（検索、記録、履歴と詳細）が途中で止まらないこと

## 証拠の残し方

- スクリーンショットとトレースは `.cache/e2e/` などの git 管理外に置く
- PR の説明に「ブラウザ確認」の節を作り、見た画面、使った幅とテーマ、見つけた問題と対処を書く。画像を貼れる場合は要所だけ貼る

## この確認で分からないこと

- moto は presigned POST のポリシー（サイズ上限・署名・期限）を検証しない（`docs/LOCAL_DEV.md`）
- 解析（Bedrock）と店名検索（Google Places）はモック
- 本物の Cognito ログインはモック認証で代えている

これらは dev 環境での実機確認で人が確かめる。PR の説明の「未確認」に書く。
